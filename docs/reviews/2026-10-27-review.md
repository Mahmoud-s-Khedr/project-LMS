## Overall

The backend is in good shape. I found no tenant-isolation or payment-integrity bug in the code I read. The problems below sit around the code rather than in its core: CI, deployment, the web layer, and marketing copy that promises features the product does not have.

Strengths worth keeping:

- **Commerce never trusts client or webhook payloads.** Each Stripe event is stored first. The worker then retrieves the object from Stripe again and checks the amount, currency, customer and tax. Live-mode events are refused.
- **Checkout is idempotent across Stripe calls.** Order IDs and Stripe idempotency keys come from the user's Idempotency-Key, so a retry after a lost response does not create a second order.
- **Access depends on entitlement rows, not product state.** Grants come from frozen snapshots and carry deterministic source keys. A refund that revokes access cannot be undone by a late "paid" event.
- **Uploads are checked server-side.** The MIME type comes from an allowlist and is confirmed by reading the file's first bytes. Files go to quarantine until scanned. Size and checksum are verified, and there is a per-workspace quota. Learners get downloads only through short-lived presigned URLs, after the access policy approves them.
- **Assessments hide answer keys.** Questions are delivered through strict schemas that carry no answer key. Deadlines are enforced on every read and write, not only by the worker.
- **Certificates render safely.** All fields are HTML-escaped, the accent colour must be a hex value, and a strict CSP blocks scripts and network access.
- **Auth is solid.** It includes:
  - Argon2id with a dummy hash for unknown users, so response timing does not reveal accounts.
  - Refresh rotation with a 30 s grace window and family revocation on token reuse.
  - Origin check plus double-submit CSRF.
  - Registration that does not reveal whether an email exists.

### 1. High — CI cannot pass as written (`.github/workflows/ci.yml`)

Three separate problems, each enough to fail the run:

1. **Formatting.** `pnpm format:check` fails on 144 files, and it is the first gate.
2. **Migration status.** `prisma migrate status` runs *before* `migrate deploy`, on an empty database. Prisma exits non-zero when migrations are pending, so this step fails on every fresh CI database.
3. **Missing S3 settings.** The job sets no `S3_ACCESS_KEY_ID` or `S3_SECRET_ACCESS_KEY`, and has no MinIO service. Both values are required by `apps/api/src/config/env.ts` and have no default. CI has no `.env` file either, so the API refuses to start for `test:security` and the path-parity check.

The local runs passed only because `.env` and Docker MinIO exist on this machine.

**Fix:**
- Run `pnpm format` once and commit the result.
- Drop the status step, or move it after `migrate deploy`.
- Add a MinIO service, the S3 env vars and the bootstrap-storage step.

### 2. High (production) — rate limits key on the proxy IP and live in memory

`apps/api/src/main.ts` never sets `trust proxy`, so `req.ip` is the load balancer's address. That address is the throttler key, so once deployed behind the ingress that `docs/DEPLOYMENT.md` describes, all users share one bucket. Login and register allow 5 requests per minute, which means one bucket locks everyone out.

The `ThrottlerModule` also uses its default in-memory store, so every API replica keeps its own count.

**Fix:**
- Set `app.set('trust proxy', <hop count or CIDR>)` from config.
- Use a Redis throttler storage; Redis is already a dependency.

### 3. High (product / legal) — marketing copy promises things the product doesn't do

Files: `apps/web/src/features/marketing/data/mock-data.ts`, rendered by `landing-page.tsx`.

- **Payouts.** FAQ `faq_04` says instructors "connect their Stripe account… routes payouts directly to your bank account" and "generates a compliant invoice". There is no Stripe Connect integration, no payout ledger, and `taxTotal` is always 0. Every sale from any instructor workspace is paid into the single platform Stripe account.
- **Platform plans.** `PRICING_PLANS` lists three plans: Learner pass $39, Creator Studio $79, Academy $249. None of them exists as a product, and the features they list aren't built: "40+ courses", "7-day free trial", "15% member discount", "25 seats", "webhook/API integrations", "0% platform fee".

This is more than copy. Anyone can register as an instructor (`auth.service.ts` creates an ADMIN workspace for them), create products and sell. The money would go to you with no way to pay them out. Before taking real payments, decide on the business model: platform-owned catalogue only, or a marketplace on Stripe Connect.

**Fix:** remove the pricing section and the FAQ claims, or build what they describe.

### 4. Medium — open redirect after login

Files: `apps/web/src/features/auth/components/login-form.tsx:59`; the same check is in `register-form.tsx:89,323`.

The guard is `startsWith('/') && !startsWith('//')`, and `/\evil.example` passes it. Browsers and `new URL()` treat a backslash like a forward slash, so `new URL('/\\evil.example', origin)` resolves to `http://evil.example/`. A phishing link such as `/login?redirect=/%5Cevil.example` therefore sends the user to an outside site right after a real sign-in.

**Fix:** add one shared `safeRedirect()` helper and use it in all three places. It should resolve the path with `new URL(value, location.origin)`, require the same origin, and return `pathname + search + hash`.

### 5. Medium — `TENANCY_MAIL_KEY` has a public default with no production guard

File: `apps/api/src/config/env.ts:27`.

The key that encrypts raw invitation tokens in the outbox falls back to a fixed value committed to the repo (`MDEyMzQ1…`). If production forgets to set it, anyone with read access to the database or its backups can decrypt pending invitation tokens and accept them. `AUDIT_IP_HASH_SECRET` already refuses to run in production without a value; this key has no such check.

**Fix:** in `validateEnvironment`, reject a missing key, or this known default, when `NODE_ENV=production`. While there, require `CONTENT_HOST_KEY` and `AUDIT_IP_HASH_SECRET` in the same place.

### 6. Medium — no security headers on the web app

File: `apps/web/next.config.ts`.

The config sets no `headers()`. There is no CSP, no `frame-ancestors` / `X-Frame-Options`, no HSTS and no `Referrer-Policy`. `helmet` protects only the API, so checkout, admin and grading pages can be framed by another site (clickjacking).

**Fix:** add a baseline header set in `next.config.ts`. A strict `frame-ancestors 'none'` costs nothing.

### 7. Medium (launch blocker) — payments accept Stripe test keys only

Files: `env.ts` (the `STRIPE_SECRET_KEY` regex `^sk_test_`), `payment-provider.ts` (`enabled` requires `sk_test_`), and `commerce-worker.service.ts` (live-mode sessions and events are refused).

This is deliberate and is a sensible guard for now. Be aware that going live means changing all three places together, and the paid browser journey has never run against real Stripe.

### 8. Medium — no Dockerfiles, although the runbook deploys containers

`docs/DEPLOYMENT.md` describes rollouts and rollbacks by container tag. The repository has no Dockerfile for `apps/api`, the worker or `apps/web`. The certificate worker also needs Chromium at `CERTIFICATE_CHROMIUM_PATH`, and media processing needs ClamAV and ffmpeg. None of that is packaged anywhere.

### 9. Low — `@Throttle` on checkout sessions has no effect

File: `apps/api/src/modules/commerce/commerce.controller.ts:209`.

`@Throttle` only attaches metadata. `CommerceController` has no `@UseGuards(ThrottlerGuard)`, and there is no global throttler guard, so checkout-session creation is not rate limited.

**Fix:** add the guard to the controller.

### 10. Low — Swagger UI is public in production

File: `apps/api/src/main.ts`.

`/api/docs` is mounted unconditionally. Gate it with `NODE_ENV !== 'production'` or put it behind auth.

### 11. Low — dependency audit

- **postcss (3 high, 2 moderate):** reached through `next`. These are build-time issues; upgrade Next when a patched release ships.
- **multer DoS (high):** reached through `@nestjs/platform-express`. The API has no file-upload interceptors, because uploads go straight to S3 by presigned URL, so the vulnerable code never runs.
- **js-yaml (moderate):** reached through `@nestjs/swagger`.

Bump the packages when convenient. None of these blocks a release.

### 12. Low (scalability) — Stripe calls run inside DB transactions that hold advisory locks

Checkout (`checkout.service.ts`) and the reconciler make Stripe HTTP calls inside Postgres transactions with a 60 s timeout. Each one holds a pool connection and advisory locks. `commerce-reconcile:<workspace>` serializes all fulfillment for a workspace.

This was a deliberate trade for correctness and is fine at current scale. Load-test it before running a large workspace: a slow Stripe API under load could use up the connection pool.

### 13. Info — `TENANCY_MAIL_KEY` description in the deployment docs

`docs/DEPLOYMENT.md:56` calls it a key for "invitation HMACs". It is actually an AES-256-GCM encryption key, which matters when rotating it: the previous key must go into `TENANCY_MAIL_PREVIOUS_KEYS`.
