# Development fixtures

Run `pnpm --filter @lms/api db:deploy`, `pnpm --filter @lms/api db:seed`, then `pnpm --filter @lms/api db:generate` from the repository root. The seed permits only development/test against local PostgreSQL. Never enable demo credentials in a deployed environment.

Development-only logins: `admin@example.test`, `owner@example.test`, `instructor@example.test`, `ta@example.test`, `student@example.test`, `other-student@example.test`. Each initial password is `Lms-demo-only!2026`. Accounts are email-verified, use Argon2id hashes, and have no tokens or real personal data. Passwords and any existing fixture edits are preserved on rerun. The fixed hash salt is strictly for deterministic development fixtures; production identity always uses random salts.

`fixtureId(key)` derives stable UUIDs from namespaced keys; business timestamps start at 2026-01-01 UTC and configured demonstration access ends at 2030-01-01 UTC. UUIDs and payloads are database fixtures, not public response DTOs. Decimal grades are stored exactly; API serialization must return decimal strings and BigInt digit strings per P1-C. The seed uses an advisory transaction lock to serialize concurrent reruns and inserts all fixtures atomically. It never truncates tables or updates existing immutable versions/history. Missing records are restored by stable-ID upserts; natural-key collisions with different IDs fail visibly instead of silently taking over data.

The personal workspace has a free self-paced course. The academy has admin/instructor/TA/student memberships, a paid self-paced course and an open cohort course. Each course has assigned staff and a published text introduction. TA can grade but cannot edit or manage learners. Student enrollments include FREE, MANUAL, ORDER_ITEM and SUBSCRIPTION sources, including three independent grants on the same paid enrollment.

The bank includes all nine question types with matching keys/options. QUIZ, ASSIGNMENT and timed EXAM each have retired version 1 and published version 2. The assignment retains a graded essay from version 1 and two GradeEvents (initial and corrected award), while version 2 adds a file-upload question. This demonstrates retained snapshots without claiming a storage object exists for a historical submission. All required lessons in initial enrollment policy snapshots are published introductions; assessments are optional examples.

Active one-course, bundle and monthly subscription products have USD prices. A normalized percent coupon, paid order, frozen OrderItemCourse, successful local ledger payment and subscription supply purchase/access examples. Optional Stripe fields are NULL; required customer/subscription mappings use `fixture-only:*`, deliberately **not usable Stripe IDs**. No provider calls, mail, jobs or outbox events are emitted. Live checkout/portal/renewal flows must create genuine Stripe **test-mode** mappings through commerce and must not send fixture-only mappings to Stripe. The subscription's broad date range is a static access example, not a simulated renewal clock. These fixtures do not assert end-to-end module or external-service acceptance.
