## Code review — what holds up

- **Auth guard** (`apps/api/src/common/authz/jwt-auth.guard.ts`): HS256 pinned, issuer/audience checked, session + user status re-read from the DB on every request.
- **CSRF** (`apps/api/src/modules/auth/csrf.guard.ts`): exact Origin match plus constant-time double-submit comparison, applied to register/login/refresh/logout.
- **Refresh rotation** (`apps/api/src/modules/auth/auth.service.ts:163`): user-row lock, single child per parent, reuse revokes the family. Confirmed live.
- **Login vs password change race** (`auth.service.ts:147`): a password change during Argon2 verification blocks session creation.
- **Tenant isolation** (`apps/api/src/common/authz/policy.service.ts`): course/workspace pair resolved from the DB, so a forged ID cannot authorize another tenant. TA capabilities are per-flag. Staff role must match workspace role (`tenancy.service.ts:885`).
- **Events** (`apps/api/src/modules/events`): leases via `FOR UPDATE SKIP LOCKED`, stable BullMQ job IDs, transactional per-consumer receipts, dead-letter + audited replay.
- **Database**: no cascading deletes on financial/history tables, 119 CHECK constraints, partial unique indexes for one open attempt / one published version.
- **Web session**: access token in memory only, `localStorage` holds only the active workspace ID; middleware checks just the `lms_session` hint; the client guard uses the shared single-flight refresh.
- Repo scan: no `any`, no `dangerouslySetInnerHTML`, no unsafe raw SQL outside one test, no TODO/stub markers.
